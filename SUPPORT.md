# Support

Where to get help with SoulOS.

## Questions and how-tos

1. Read the [docs index](docs/README.md) — start with [My first sidecar](docs/tutorials/my-first-sidecar.md) or [Troubleshooting](docs/guides/troubleshooting.md).
2. Search [existing GitHub Issues](https://github.com/mziqudhd92/soul-os/issues) and Discussions (if enabled).
3. Open a **Question** / discussion-style issue, or use the [feature request](.github/ISSUE_TEMPLATE/feature_request.yml) / [bug report](.github/ISSUE_TEMPLATE/bug_report.yml) forms.

## Bugs

Use the bug report template and include:

- Kernel / compose setup (`docker-compose.yml` vs `docker-compose.sidecar.yml`)
- RFC 7807 `code` from the response body (if any)
- Output of `python3 scripts/soulos-doctor.py --kernel <url>`

## Security vulnerabilities

**Do not** file public issues. Follow [SECURITY.md](SECURITY.md).

## Code of Conduct

Participation is governed by [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

## Response expectations

This is a volunteer-maintained open-source project. Maintainers aim to triage new issues within a few business days; there is no SLA. Pull requests with tests and docs updates are reviewed faster than drive-by feature requests.

## Commercial / Cloud

SoulOS Cloud hosting is separate from this MIT kernel. For Cloud account issues, use the contact channel provided in your Cloud dashboard — not this repository’s issue tracker.
